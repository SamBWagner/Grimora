## Release

- Release mode: automatic immediately after approval; phased release disabled

1.5 is an app-side feature release that builds on 1.4's Scry (camera card
recognition) and living-foil work. The headline additions are **Scry price
tiers** (scanned cards show their value, with a per-tier accent colour, border,
value badge, and an escalating "level-up" sound; four thresholds are editable in
Settings), and a Commander **"Re-scan Deck"** flow (scan a physical Commander
deck and reconcile it against the stored list, accepting or discarding the whole
diff at once). It also improves bulk-scan focus (an AF-settle coordinator
replaces fixed timers, plus a tap-to-focus hint), reads collector numbers on
old-border retro reprints, and makes value-tiering foil-aware so foil-only
printings (e.g. Bria) are valued correctly. Alongside Scry, it fixes responsive
layout on small iPhones (Collections overview and the New List source picker),
makes dashboard collection tiles reorderable and pin-aware, and rotates Aftermath
cards the correct way with matching artwork controls.

No new permissions are introduced. The Commander "Re-scan Deck" flow reuses the
existing on-device camera recognition (`NSCameraUsageDescription`) already shipped
in 1.4; there is no reviewer-relevant behaviour change beyond that. It ships
against the existing managed catalog API; no catalog redeployment was performed as
part of this cut.

## Headline Changes

- Scry price tiers: single-mode confirm chip and review sheet show the scanned
  card's USD value, take a tier accent (neutral <$1, green ≥$1, blue ≥$5, purple
  ≥$10, gold+border ≥$25), and play a per-tier "level-up" jingle; thresholds are
  editable in Settings → "Scry Price Alerts". Value is resolved foil-aware via the
  value guide (`scanTierPriceUSD`), so foil-only printings are tiered correctly.
- Commander "Re-scan Deck": camera reconciliation of a physical Commander deck
  against the stored deck; exact-printing diff over commander+mainboard, singleton
  double-scan voiding, whole-diff Accept/Discard applied in one undoable mutation.
- Scry bulk focus: `ScryFocusSettle` AF-settle coordinator (observes
  `isAdjustingFocus`) replaces fixed focus timers; centered continuous AF by
  default; tap-to-focus hint + haptic. Retro (1997) old-border reprints now parse
  the bare collector number on the copyright line.
- Collections overview responsive layout on small iPhones (header ViewThatFits;
  compact-aware grid minimum) and a size-class-adaptive New List source picker
  (full-width rows on compact widths; un-clipped card grid on regular widths).
- Dashboard collection tiles are long-press reorderable across platforms, and
  dropping a tile onto an opposite pin-state tile pins/unpins it; pinned tiles show
  a pin glyph. Order and pin state sync via CloudKit with no schema changes.
- Aftermath cards rotate counterclockwise (new 270° case) so both halves read
  upright; the artwork-cycle button icon reflects the real motion plan; the compact
  printing gallery reserves a landscape box for turned cards.

### Accepted known-failures (Scry honest corpus gate)

Two Scry recognition tests report failures at this cut and are **accepted as known
reds for 1.5**, not release blockers:

- `ScryCorpusTests.testCorpusResolvesEveryCropAgainstRealCatalog`
- `ScrySceneTests.testDetectsAndResolvesSubjectInEachScene`

Why this is not a regression (verified this cut):

- Commit `46b6e01` deliberately made the corpus gate **honest** — `knownFailure` is
  now a historical tag that no longer *exempts* a card from the gate, so genuinely
  hard cards that fail to auto-scan surface as reds instead of being hidden.
  Commit `e02ae05` explicitly records "Terastodon remains an honest red."
- Running the same two test classes on `main` against the **same on-disk catalog**
  passes (`TEST_RC=0`): the shared hard cards (terastodon, alpha-authority,
  angelic-skirmisher, mountain-one-270-foil, arcane-signet, brilliant-restoration,
  beamtown-beatstick, fiery-confluence) fail *identically* on `main` — they are
  simply marked `✗ knownFailure (still failing)` and exempted there. So this is the
  honest-gate policy surfacing pre-existing hard cards, **not** catalog drift and
  **not** a recognition regression.
- A few cards changed from auto-accept to disambiguation (ancestral-katana,
  siphon-insight) — the deliberate precision hardening from `4f76beb`
  (`exactKey` no longer auto-accepts a set+number key when the read name doesn't
  match the keyed printing). The card still resolves correctly; it now requires one
  tap in the printing picker. siphon-insight's fullres OCR read a garbage name,
  exactly the case the hardening protects against.
- The rest are newly-imported hard cards (sword-of-kaldra, sol-ring, edgar-markov,
  last-chance, harmonized-crescendo, blacksmiths-skill, monstrous-rage).

Safety net intact: both `testPreviewScanNeverWronglyAutoCommits…` precision tests
pass, and soft-focus reports **0 wrong auto-accepts at every blur radius**. No card
is ever confidently mis-filed. Auto-accept rate is equal-or-better than `main`
(crops 143/181 ≈ 79% vs main 48/64 ≈ 75%; scenes 141/180 ≈ 78% vs main 42/65 ≈
65%).
