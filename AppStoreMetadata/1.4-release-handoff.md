1.4 is an app-side feature release. The marquee addition is **Scry** — on-device
camera card recognition (iPhone/iPad) that files recognised cards into a new
"Scanned" collection — alongside a **living-foil** overhaul (synthetic
holographic finishes rendered by a Metal shader across search, grids, and detail,
with per-entry finish persistence and multi-finish support), a manual
"Sync with iCloud" action, pull-to-refresh card-data updates, a resizable macOS
detail pane, and an animated launch screen. It ships against the existing managed
catalog API; no catalog redeployment was performed as part of this cut.

The new camera permission (`NSCameraUsageDescription`) is the only
reviewer-relevant behaviour change; see App Review Notes in `listing-copy.md`.

## Headline Changes

- Scry: on-device (Vision) camera recognition into a lazily-created "Scanned"
  system list; single-scan and movement-gated bulk modes; uncertain cards fall to
  a ranked printing picker rather than guessing.
- Living foil: one GPU-shader renderer for foil/etched/special-treatment finishes
  across search, grids, and detail; per-printing session finish + per-entry
  persisted `selectedFinish`; foil pricing.
- Manual "Sync with iCloud": pull-to-refresh on iOS/iPadOS/visionOS; File-menu
  command (Cmd-R) and toolbar button on macOS.
- Pull-to-refresh card-data update check on the Cards (search) screen (touch).
- macOS: card detail is a resizable, persisted column with a draggable divider
  and double-click-to-fit.
- Favourites and Scanned lead the sidebar as a headerless system-list group.
- Animated launch screen (disabled under UI tests / `GRIMORA_DISABLE_LAUNCH_SCREEN`).

## Fix landed during the cut

- **Scry soft-focus precision guard** (`ScryCardResolver`). The pre-release test
  gate's `ScrySoftFocusTests` caught one wrong auto-accept: a blurred scan of
  Generous Gift `[blc 106]` mis-read the collector number `106` as `100`, and
  because only the DMC printing is `#100`, Tier A′ (name + collector number)
  auto-accepted the wrong printing of the right card — violating the suite's
  cardinal invariant that blur must never cause a wrong auto-accept. Surfaced by
  the freshly-rebuilt local test catalog (the shipping Scryfall data carries the
  same printings), not a regression in the 1.4 diff.

  Fix: in Tier A′, a lone collector number is a trustworthy unique key only if no
  *other* printing of the same card sits a single OCR error away
  (`collectorNumbersOCRConfusable`: equal-length single substitution of three or
  more characters, e.g. `106`↔`100`). When such a sibling exists and no set code
  corroborates the read, the resolver surfaces the printing picker (with the
  correct printing present) instead of auto-accepting. Short numbers (a card is
  `#6` in many sets) and length changes (`267` vs `267p`) are deliberately not
  treated as confusable, so recall is unaffected. Corpus auto-accept held at
  `48/64` and soft-focus wrong-auto-accepts went to `0` at every blur radius.
  Added `ScryRecognitionTests` coverage (confusable-sibling disambiguation, two
  recall guards, and the confusability truth table).
