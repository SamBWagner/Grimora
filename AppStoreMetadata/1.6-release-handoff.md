1.6 is an app-side feature + reliability release. The headline additions are
**Commander decks** (a collection is now either a plain Collection or a Commander
deck; Commander decks enforce singleton — a second copy of a card is blocked
across printings, with an "Add Anyway" escape hatch, plus "Choose Commander" and
"Remove Duplicate Copies" actions), **Reorganise by Type** (file a deck's cards
into type-named categories in one action) and **multi-category tags** (an entry
keeps one primary category plus any number of secondary tags, synced and shown as
tags/badges). Alongside that, **iCloud sync is made dependable**: cross-device
edits used to revert to an older copy and lock a list to one device's version —
fixed by a monotonic logical clock and a mirror trigger so every entry edit
(quantity, printing, foil, zone/category moves) propagates and holds. An
append-only **change ledger** rides on top as history, synced as pure-union
records.

No new permissions are introduced; no account is required; iCloud remains
optional. The change ledger stores the user's own edit history inside their
private iCloud (CloudKit) container — no new data collection and no third parties.

**Infra step performed for this release:** the new CloudKit record type
`GrimoraChangeLogEntry` (plus its indexes) was deployed from Development to the
**Production** CloudKit schema before the Production archive, so the ledger syncs
on shipped builds. Existing record types are unchanged (the deploy is additive).

## Headline Changes

- Commander decks: `CardCollectionRuleset` reduced to `.none` (Collection) and
  `.commander`; a single "Commander Deck" toggle replaces the old multi-format
  menu. Commander decks are singleton — `appendCard(enforceRulesetLimits:)` blocks
  a duplicate by oracle id (across printings; basics + "any number" exempt) with an
  "Add Anyway" confirmation, and the ruleset warning panel gains "Choose Commander"
  and "Remove Duplicate Copies". An idempotent migration rehomes decks tagged with
  the six retired constructed formats.
- Reorganise by Type + multi-category tags: one-tap filing into type-named
  categories (Creatures, Instants, Lands, …); entries carry a new
  `secondary_category_ids` column of extra tags, synced through iCloud and
  archive import/export, shown as a tag line in list view and a badge on grid tiles.
- iCloud sync reliability (the revert-loop fix): merge authority moved off raw
  wall-clock `updatedAt` to a monotonic logical clock (`CardDatabase+HLC.swift`)
  that advances past the newest instant pulled from any device, so a lagging device
  catches up instead of reverting. A new `trg_card_list_entries_sync_updated_at`
  mirror trigger + `updated_at` stamping on every entry mutation fixes entry edits
  that had silently stopped propagating after the earlier upload-diff optimisation.
- Change ledger: append-only `change_log` (`ChangeLogEntry`) records every user
  action at the point of interaction, synced as `SyncEntityType.changeLogEntry`
  (CloudKit `GrimoraChangeLogEntry`) via a conflict-free union; per-sync snapshot
  bounded to the newest 1000 rows.
- Earlier in the 1.6 line: the CloudKit "iCloud sync is unavailable" stall
  (partial-failure treated as fatal) and the full-library re-upload churn were
  fixed, with Settings → Sync diagnostics and a macOS toolbar sync spinner.
