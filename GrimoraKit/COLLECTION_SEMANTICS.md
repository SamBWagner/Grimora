# Read-only collection semantic profiles

`CardDatabase.collectionSemanticProfile(for:entries:policy:)` hydrates printing records from the active catalog and returns `unavailable` for legacy or unenriched catalogs. Available empty, single-card, isolated and partial profiles are valid. Callers supply a captured list and entries; the API never changes either.

The default policy includes mainboard entries and explicit commander-zone entries only when the ruleset is Commander. It excludes sideboard and maybeboard; each requires an explicit policy opt-in. Unsupported stored commander zones are excluded, not normalized into mainboard. The existing ruleset validator reports warnings for the stored configuration. Invalid decks remain inspectable.

Meaningful Oracle IDs collapse alternate printings into one semantic node. Nil, empty and whitespace-only IDs use printing identity. The smallest printing ID present in the list is the stable representative. Each node retains entry IDs, original zones and normalized positive quantities. Copies never multiply presence, support counts or edges. Missing records remain entry evidence and count once per unresolved printing in coverage's denominator. Entries from another list are ignored; duplicate entry IDs are rejected.

Features use the related-card scorer's gameplay-enabled concepts, catalog IDF, maximum direct membership weight and 0.5 attenuation per hierarchy level. Breadth-first expansion retains one canonical strongest path per direct assertion, with ordinal path ties. It avoids recursive/exponential path enumeration and terminates on cycles. Each assertion retains its direct weight, source, annotation and exact chosen path; support records retain effective weight and the union of sources from every enabled inherited route, calculated by finite source-set propagation separately from canonical paths. Similarity-disabled concepts stop traversal and cannot affect coverage or links. No concept-kind ontology or multiplier is invented.

Dominant importance is the sum of each unique support card's effective membership weight times catalog IDF, divided by eligible unique cards. Support count, coverage, specificity, identities and provenance accompany it. An edge's weight is IDF-weighted cosine similarity using every shared feature. Explanations expose the strongest shared contributions and exact supporting assertions, capped by policy, with total shared-concept count recorded. Degrees sum edges in stable identity order. The graph contains list-internal pairs only; there is no catalog-wide all-pairs artifact.

“Few semantic links” means weighted degree strictly below the measured list median. Evidence distinguishes missing tags, no shared enabled concepts and a positive degree below the median, and states when incomplete coverage affects measurement. One-card and all-isolated lists have no below-median classifications. Highly connected cards are all positive-degree cards tied for the measured maximum. These are measurements, not quality judgments, diagnoses or suggested cuts.

The SHA-256 content fingerprint includes list identity, ruleset, entry identity, printing, quantity, zone and versioned policy. Presentation order, dates, categories and list name are excluded. A bounded, database-instance-local cache is cleared under lock by every catalog generation change, including installs, card replacement, streaming reset/append and semantic replacement. Extraction/hydration uses one cancellable lock acquisition and explicit attached-schema semantic reads. Expansion, pair scoring, sorting and assembly run outside the lock. A generation change before publication retries the entire extraction. Cached and recomputed results have the same contract.

`GrimoraAppModel.loadSelectedCollectionSemanticProfile` is an explicit loading integration for future Insights. It publishes only the current selection/content and cancels on selection, entry or ruleset changes. This milestone adds no Insights UI, recommendation actions, automatic list edits, importer changes or release-version bump.

Run the focused contract tests with `swift test --package-path GrimoraKit --filter CardCollectionSemanticProfileTests`. The unconditional `CardCollectionSemanticProfileRuntimeTests` benchmark seeds the production database with 100-card Commander fixtures for 75% coverage and full connectivity, prints cold/warm latency and resident memory before/after, and also runs in each app scheme's dedicated profile test target. iPhone and iPad destinations must be invoked and recorded separately.
